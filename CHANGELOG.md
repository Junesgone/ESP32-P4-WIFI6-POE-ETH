# Changelog

All notable changes to this project are documented here.
The format is based on [Keep a Changelog](https://keepachangelog.com/), and this
project adheres to [Semantic Versioning](https://semver.org/).

## v0.0.9 — 2026-11-15

Conversation manners release: 小新 waits until you have actually finished the
sentence before it answers.

### Fixed

- **The board started answering in the middle of a question.** The trailing
  silence that closes an utterance was 700 ms, but a normal thinking pause in
  Chinese is often longer, so the first half of a sentence was sent to ASR /
  the model while the person was still talking. The VAD hangover is 1100 ms now
  and, after it elapses, the utterance is held for another 900 ms resume grace:
  the board keeps listening, and if speech starts again inside that window the
  **same utterance is extended** (its audio is still buffered) instead of
  producing an early turn and a second turn for the rest. Two consecutive
  speech frames (40 ms) are required before extending, so single-frame room
  noise cannot hold a finished question open.
- **The supervisor no longer interjects while the user is talking.** Its
  "pipeline idle" check did not include the capture path, so a long question
  with pauses could let it chip in. It now asks the main loop whether the user
  is currently speaking (VAD open or inside the resume grace) and stays quiet.
- **Reply token budget was still 400 in the build scripts** (the Kconfig default
  had been raised to 900/1600, but `config/deepseek.defaults` generated by
  `tools/build_voice_logger.sh`/`.ps1` kept overriding it). With thinking
  enabled the reasoning tokens are counted against it, so search-minded
  questions ended with `finish_reason: "length"` and no answer at all.
  The generated defaults and the Kconfig default are 1600 now.

### Changed

- `CONFIG_VOICE_VAD_HANGOVER_MS` 700 -> 1100, new
  `CONFIG_VOICE_VAD_RESUME_GRACE_MS` (default 900),
  `CONFIG_VOICE_VAD_MAX_UTTERANCE_MS` 20000 -> 30000 (merged sentences are
  longer). A reply now starts ~2 s after the speaker actually stops.
- Firmware version 0.0.9.

## v0.0.8 — 2026-11-15

Latency + memory release: a spoken turn no longer pays three TLS handshakes, and
the board remembers each recognised person across reboots.

### Added

- **TLS session reuse.** `app_ds_http.c` keeps one keep-alive HTTPS connection to
  api.deepseek.com and serves ASR, TTS, Search, Fetch and non-streaming chat from
  it; the chat SSE connection (the edge closes it) resumes from a TLS session
  ticket instead of redoing the certificate exchange. Measured: first Search
  4.7 s -> 0.4-0.5 s afterwards; chat first answer token 3.2-4.6 s -> 0.5-1.4 s;
  TTS connect 3.1-3.9 s -> 35-50 ms. A spoken turn drops from ~20 s to a few
  seconds before the first word. Console `dshttp` shows requests / handshakes /
  reuses.
- **Per-person conversation memory** (`app_memory.c`). Each turn is stored per
  speaker label on the TF card (`/sdcard/conv/people/<speaker>.txt`, tab
  separated), the last 4 turns are injected as background when that person talks
  again (across reboots), the model has a `recall_memory` tool, and the console
  gained `memory`, `memory show <name>`, `memory search <text>`,
  `memory clear [name]`. Files rotate past 48 KB. Verified on hardware: after a
  reboot the same voiceprint loaded "2 of 2 remembered turns" and answered
  "你刚让我用一句话介绍自己，还问了上海今天的天气".
- `CONFIG_ESP_TLS_CLIENT_SESSION_TICKETS=y` in the board defaults.

### Fixed

- SD card writes failed with `sdmmc_cmd: allocate_dma_buf: not enough mem` while
  the persistent TLS client owned a large part of the internal heap: the TF card
  now reserves a DMA buffer **after** the ESP-Hosted SDIO link is initialised.
  (Reserving it earlier broke the SDIO card init and took Wi-Fi down completely.)
- System prompt buffer moved to PSRAM and the shared-connection RX buffer reduced
  to 2 KB, so a turn leaves ~19 KB of internal heap free instead of the old
  ~50 KB; the firmware logs a `LOW internal RAM` warning below 16 KB.
- The chat SSE reader no longer depends on the server closing the stream after
  `[DONE]` (it does not close it); it stops at `[DONE]` and closes the socket.

### Notes

- The WebSocket TTS path stays experimental/off by default (unchanged from
  0.0.7); the streaming POST now reuses the connection, which is the best of both.
- Per-speaker memory makes voiceprint labels meaningful: enrol with
  `enroll <name>` and that person's conversations are remembered under their
  name; unenrolled regular voices accumulate under 人N.

## v0.0.7 — 2026-11-15

Live microphone fixes: the voice path had stopped answering spoken input, and
the TLS handshakes did not fit next to the audio pipeline.

### Fixed

- **The board stopped answering any spoken question.** The utterance worker
  already takes the cloud lock around a whole turn; v0.0.6 took the same
  non-recursive mutex a second time inside the turn, so the first clip deadlocked
  the worker (and every later clip just piled up in the capture queue while the
  lock stayed held). The second take is gone; the lock is taken exactly once per
  turn. Verified on hardware with the on-board microphone: "小新你好，请用一句话
  介绍一下你自己" -> "你好呀，我是小新，就住在这个家里的语音助手…" spoken back.
- **TLS handshakes failed with `mbedtls_ssl_setup -0x008D` /
  `PSA signature verification failed (-141)`** once the AFE/esp-dl pipeline was
  live: the 16 KB mbedTLS input buffer left too little internal RAM for the
  certificate/signature work. The TLS record buffers are now 8 KB in / 2 KB out,
  which fixed both errors (search, ASR, chat and TTS all complete their
  handshakes now).
- WebSocket TTS no longer stalls a reply: the connect timeout is 4 s, and after
  two consecutive failures the streaming POST is used directly for 5 minutes
  before the WebSocket is probed again.

### Changed

- WebSocket TTS is now **off by default** (`CONFIG_VOICE_TTS_WS`). Measured on
  this board it gives no latency advantage over the streaming POST - the
  service sends no audio before `finish_text` on either transport - and the
  esp_websocket_client handshake still fails intermittently
  (`esp_transport_read -135` / connect timeout). The streaming POST with
  `format:"pcm"` is the default and works: measured 3.1-3.9 s to connect,
  first audio 4.3-5.2 s, playback starved 0 ms.
- Certificate verifier diagnostics: a non-zero verify flag at any depth is now
  logged with subject/serial, and the DigiCert root pin logs why it did not
  match. The Root G2 seen in the chain has a 99-byte subject that does not carry
  the expected CN string, so the bundle callback (which now succeeds) handles it.
- Firmware version 0.0.7.

### Measured on hardware (firmware 0.0.7)

A spoken question -> spoken answer turn: ASR 4.2 s (of which ~3.5 s is the TLS
handshake), LLM 3.4 s, TTS 3.1 s to connect + first audio 4.3 s, then the reply
is played. Everything is serialised on one TLS session at a time by design.
Standalone Search API: 4.2 s per call on the board (0.5 s from a PC), again
dominated by the handshake. Keeping a TLS session alive between the ASR / chat /
TTS calls is the next latency lever.



DeepSeek full-suite release: the whole DeepSeek App conversation stack now runs
on the board through the new application APIs — no third-party LLM/ASR/TTS vendor
is required any more.

### Added

- **Built-in web search** (`deepseek_web_search`) and **deep thinking search**:
  thinking mode is on by default (`reasoning_effort` configurable low/high/max),
  and with the web tool declared the service searches, opens pages and checks
  facts across several reasoning steps before answering. Citations come back in
  the last stream chunk and are logged.
- **URL reading** (`deepseek_read_url`): links in the user message are fetched by
  the service; the returned `server_tool_calls` are echoed back on the next turn
  so a page that was read stays in context.
- **File input**: Files API upload with server-side parsing
  (`text_recognition` / `rich_layout_recognition`) followed by a
  `{"type":"file","file_id":...}` content part — the same two-step flow as
  uploading a file in the DeepSeek App. Images use `purpose=user_data`.
- **Standalone tool APIs**, each usable on its own: `POST /v1/tools/search`,
  `/v1/tools/fetch`, `/v1/tools/ocr`, `/files`, `/v1/tools/asr`,
  `/v1/tools/tts`.
- **Model content safety** (`safety_check: {"level":"high"}`): input and output
  review; refusals are answered with a short spoken refusal.
- **Conversation titles** (`title.enabled`, stored with the turn on the TF card)
  and the **user-metadata marker** (`latest_reminder` with date, weekday, city,
  platform and language).
- **DeepSeek ASR** replaces SiliconFlow SenseVoice (`POST /v1/tools/asr`,
  16 kHz mono WAV, language auto-detected, ≤ 8 MiB / 120 s).
- **DeepSeek streaming TTS over WebSocket** replaces CosyVoice2:
  `wss://api.deepseek.com/v1/tools/tts` sends `{"event":"text"}` chunks followed
  by `{"event":"finish_text"}`, and the 24 kHz PCM frames are resampled to
  16 kHz and played from a PSRAM jitter buffer as they arrive. A streaming HTTP
  POST is the fallback; the on-board ESP-SR voice remains the offline fallback.
  Voices: stella (female) / tide (male).
- Serial console: `ds` status, `think`, `websearch`, `readurl`, `safety`,
  `title`, `effort`, `fetch`, `ocr`, `askfile`, `asr`.
- `tools/build_voice_logger.sh` — Linux/macOS build+flash script equivalent to
  the PowerShell one.
- The turn record on the TF card now carries a `ds` object with the finish
  reason, search/link-read counts, thinking size, first-content latency,
  citations and the conversation title.

### Changed

- One DeepSeek key drives chat, ASR, TTS and all tool APIs; the SiliconFlow key
  is optional and only used by the legacy fallback path.
- `app_deepseek.c` was rewritten around the full-suite request builder and the
  extended SSE parser (thinking deltas, server tool progress, citations,
  `server_tool_calls`, title, refusal). The SSE line buffer moved to PSRAM
  because a search turn's final chunk can be 10–20 KB.
- The client-side `web_search` function tool is no longer declared while the
  built-in web-search tool is on (one search path, not two); it stays available
  for the conversation supervisor.
- Voiceprint, persona, speaker identification, AEC/VAD and the TF-card WAV/JSONL
  logging are unchanged.
- Firmware version bumped to **0.0.6**.

### Fixed

- `max_tokens` raised to 900: with thinking on, the reasoning tokens count
  against it and 400 was truncating answers (`finish_reason: "length"`).
- Citations and conversation titles are actually collected now that the SSE line
  buffer can hold the final chunk.
- The utterance worker now takes the same cloud lock as the serial console and
  the supervisor. It used to run ASR + chat + TTS without it, so a console
  command or an interjection could open a second mbedTLS session; that second
  connection failed inside `mbedtls_ssl_setup` with `-0x008D`
  (PSA_ERROR_INSUFFICIENT_MEMORY) and surfaced as "Connection failed, sock < 0".
- All DeepSeek HTTPS/WSS clients (chat, ASR, TTS, Search, Fetch, OCR, Files) use
  the pinned-certificate verifier; ASR and TTS previously used the plain CA
  bundle and intermittently failed the handshake with `-0x3000`.
- The TTS streaming POST sent `Authorization: Authorization: Bearer ...`
  (the WebSocket-style header line was reused as the HTTP header value) and got
  401; the two paths now build their headers correctly.
- A non-ASCII checkout path (e.g. a Chinese home directory) broke ESP-IDF's
  picolibc spec-file escaping; `tools/build_voice_logger.sh` now detects that
  and keeps the build tree on an ASCII path.

### Notes

- Boot volume is **75** (0-100, "vol <n>" at runtime). 90 clipped; 50 was too
  quiet in the room this board lives in.
- Spoken answers are capped at the first two sentences (~110 bytes) so one
  answer cannot hold the speaker for 20-30 s while the microphone is gated.
  The full text stays in the console output and the TF-card record.
- The DigiCert Global Root G2 is now pinned alongside the DeepSeek leaf, to
  work around the chain builder dropping the root link under PSA memory
  pressure (root cause of the WebSocket TTS handshake failure).

### Known issues

- The WebSocket TTS handshake fails TLS certificate verification inside the
  ESP-IDF WebSocket transport on this board (DigiCert root link rejected by the
  chain builder under PSA memory pressure). Synthesis falls back to the streaming
  HTTP POST, which works; see README section 6.3.
- A deep-thinking search turn answers with 300-400 characters, which the TTS
  then reads for ~20-30 s. The spoken-persona prompt asks for 1-3 sentences; the
  service-side web tools still produce longer formatted answers.

## v0.0.5 — 2026-10-19

Voiceprint accuracy release: discriminative weighting, session-balanced
calibration and safer anonymous-role creation.

### Changed

- Voiceprint dimensions are weighted independently by their Fisher ratio over
  hard-to-separate voice pairs (40 independent weights instead of 20 shared
  mean/std weights), and the standardisation tables were refit on a
  session-balanced set of on-device recordings.
- Accept threshold raised to 0.48 to match the new feature scale (relative
  margin stays at 0.10).
- A new anonymous role can only be seeded by utterances of at least 2.5 s, so
  VAD fragments of one sentence cannot accumulate into a duplicate role; short
  fragments can still match existing roles.
- Firmware version bumped to **0.0.5**.

## v0.0.3 — 2026-10-19

Feature release: discriminative voiceprint embedding and refit calibration.

### Changed

- Voiceprint weights are now per-dimension Fisher-ratio weights computed over
  hard-to-separate voice pairs (40 independent dimensions instead of 20 shared
  mean/std weights), and the standardisation tables were refit on an expanded
  on-device recording set.
- Pitch dimensions are no longer separately weighted; the pitch block keeps its
  0.10 mixing weight.
- Firmware version bumped to **0.0.3**.

## v0.0.2 — 2026-10-19

Maintenance release. No functional changes to the firmware.

### Changed

- Firmware version bumped to **0.0.2** (boot banner and release tag).
- Voiceprint defaults confirmed: accept threshold 0.45, relative margin 0.10.
- Repository clean-up and documentation refresh for the public release.

## v0.0.1 — 2026-10-19

Initial public release of the ESP32-P4-WIFI6-POE-ETH voice assistant ("小新").

### Added

- Full-duplex audio path: ES8311 codec + I2S, ESP-SR AFE (AEC / NS / AGC), energy VAD.
- Cloud speech recognition (SiliconFlow SenseVoice) and DeepSeek chat with function calling.
- Streaming cloud text-to-speech (CosyVoice2, raw 16 kHz PCM) with ESP-SR offline fallback.
- On-device speaker recognition: 43-dim MFCC + pitch embedding from the pre-AFE
  microphone signal, LDA-weighted, with 3-utterance averaged enrolment and anonymous
  role clustering (pending / merge / split state machine).
- Conversation modes: assistant, hybrid, monitor; optional post-reply fact-checking
  supervisor with web search.
- Device tools: volume, TTS speed, time, reminders, Wi-Fi scan/connect, voiceprint
  management, recent conversations, system status, reboot.
- WAV + JSONL conversation logging on the TF card with day folders and SNTP timestamps.
- Build/flash PowerShell script with per-board sdkconfig fragments and TTS voice-data
  partition flashing.
- Apache License 2.0, NOTICE, SPDX headers and English README.

### Fixed / hardened

- Correct AEC reference interleaving (microphone + playback reference pairing).
- Bounded cloud ASR timeouts with fast-failure-only retries and capture-queue drop
  accounting, so a bad network cannot stall the utterance pipeline.
- Supervisor gating that never talks over a reply and never repeats the last answer.
- Firmware version reporting (`App version`) in the boot banner.
